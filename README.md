### 3.2 原语不变量 `test_primitives`（26 个测试 / 180 个断言，全过）

投影长度恰为静止长度、方向与 $(x_a-x_b)$ 同向、静止位形下投影是恒等、退化边保护、

网格边计数、打包往返。

**线性（中点）弯曲约束（2026-09-22 新增，+44 断言）**：四个测试分别钉住
① **stencil 计数与顶点索引**（`(nx-2)*ny + (ny-2)*nx`、逐条核对三元组、端点不生成、
关联表 CSR 按 stencil 号升序）；
② **平直位形下弯曲力严格为 0**（用二进制精确坐标 0.25 的整数倍，所以可以断言 `== 0.0`

③ **三点链解析**：回复力逐分量等于 $-k w_v(A_c x)$、方向朝 $-y$、自由行对角 $=m/h^2+4k$、
**pinned 行必须是精确单位行**（这一条同时钉住"pinned 列必须从自由行里拿掉"）、
右端常向量 $= -k w_p C$；
④ **位形无关**：改位形后 $L$ 逐位不变（"只分解一次"的前提）、常向量只依赖 pin 位置。

**并行散射分支（2026-09-21 新增，此前完全无覆盖）**：散射在"边数 < 256 或单线程"时走串行分支，
而此前所有散射测试用的都是**单条边**的网格 —— 于是 OpenMP 分支**从未被任何测试执行过**，
这正是它的 $O(P\cdot \text{dim})$ 归约代价长期没被发现的原因（§5 第 7 项）。现在补了两个测试：
用 20×20（760 边、含 2 个 pin）的确定性扰动网格，断言
① 并行分支 == 1 线程结果 == 一份独立写出的参考实现（参考实现按边序号序，相对误差 $\le 10^{-12}$）；
② 2/4/8/18 线程各重复 4 次（共 16 次）结果**位级相同**。

**约束着色（Phase 2 新增）**：`constraintColoringIsProperAndComplete` 断言着色恰当
（同色边不共享顶点）、完备、分组 CSR 与 `colorOf` 自洽、颜色数 $\ge \Delta$，并打印实测颜色数
（2×2 → 2 色、5×5 → 5 色、20×20 与 40×40 → **6 色**；上界 $\Delta+1=7$，理论最少 4）；
`constraintColoringIsDeterministicAndTopologyOnly` 断言 1 线程与 18 线程两次着色**逐位相同**、
且**位形/刚度/pin 掩码改变不影响着色**（它是纯拓扑量）。

**全局步的三分量拆分（Phase 4c 新增）**：`globalSolveSplitsIntoThreeComponentChains` 断言
`parallelComponents() == 3`（$L=\tilde A\otimes I_3$ ⇒ 图是 3 个连通分量）；
`componentSolveMatchesFullSolveBitwise` 断言"三个分量分别求解"与"整趟求解"**逐位相同**；
`componentPinOverwriteMatchesFullPinOverwrite` 断言 pin 行的分量覆盖与整份覆盖逐位相同
（且 `components == 1` 时退回整份覆盖）。见 `docs/perf.md` §9。

**实测结论**：着色之后散射的累加顺序固定为**颜色序**（同一顶点在每一色里最多被写一次），
跨线程数与重复运行 **16/16 次位级相同** ——"与线程数无关"由此从 $10^{-12}$ 量级的经验观察
变成**结构性保证**，断言已收紧为"必须位级相同"。代价是 1 线程下多一趟种子与按颜色的循环（实测 +2 %）。
历史（Phase 1 时期，作为对照）：与边序参考的最大差 $7.1\times10^{-15}$、**位级不同**、
16 次里只有 2–3 次位级相同 —— 那正是 `schedule(dynamic, 64)` 的分块分配会变、求和分组随之变化的证据。

## 4. 修过的两个真缺陷（排查记录）

首期在"单弹簧平衡"上卡了很久，根因是两个**方向相反**的错误，都值得记下来。

### 4.1 缺陷 A：投影里加了标准 PD 没有的方向翻转（已修）

标准 PD 里 $d_c=\Pi_c(A_cx)=\ell\cdot\mathrm{unit}(A_cx)$，方向由 $A_cx$ **唯一决定**，
且必须与矩阵块 $\kappa A_c^\top A_c$ 来自**同一个** $A_c$。
早期实现在投影里加了"强制指向自由端"的人为翻转（想让 pin 端当支撑），
等于让散射与矩阵块来自不同的 $A_c$。
现在方向只由边的端点顺序 $(a,b)$ 决定，**没有任何 pin 特例**——`_verify/direction_audit.cpp` 的
A 组判据就在钉这一点（三种 pin 配置下 $d_c$ 完全相同）。

### 4.2 缺陷 B：pin 消元的补偿项 $\kappa q$ 漏了（已修，这是主因）

被 pin 的行会被覆盖成 $(L_{ii}=1,\ b_i=\bar x_i)$，等价于把该自由度从方程组中消去。
但耦合块 $-\kappa I$ 里乘 $x_{\text{pin}}$ 的那一项，原本是挂在**自由端那一行**上的 ——
行被覆盖并不会顺手处理它，必须显式搬到自由端的右端：

$$\Bigl(\frac{m}{h^2}+\kappa\Bigr)x_{\text{free}} = \frac{m}{h^2}\hat x_{\text{free}} + \kappa d_c + \kappa\,\bar x_{\text{pin}}$$

漏掉 $\kappa\bar x_{\text{pin}}$ 的表现是**自由端丢失 pinned 点的位置信息**：系统被拉向原点，
无重力、本来就在静止长度时也会自行变形，平移场景后结果改变（`pd_trans` 的第 1 组就是为此设的）。
它还会伪装成"符号错"——因为把坐标原点移到 pin 上时这一项恰好为零，很多场景看不出问题。

排查中另外两处**被我误判**、现已确认实现正确的地方，一并记下以免重蹈：

- **重力只应出现一次**，在预测步 $\hat x = x + hv + h^2g$ 里；右端只有 $(M/h^2)\hat x$，
  再加一个 $-Mg$ 就是重复计入（曾照此"修"过，属于改坏）。
- **平衡位置是 $\ell - mg/\kappa$**（能量极小值），不是 $\ell + mg/\kappa$（那是极大值）。
  符号来自重力项梯度 $+mg$（朝 $-y$）。这一点曾被写反并据此改动实现，是本项目最大的弯路。

`_verify/` 下留了排查期的若干程序（`standard_pd`、`steady`、`rhs_breakdown` 等）。
**它们不是验收工具**，其中一些的前提假设已经过期（有的注释还在按旧结论描述实现），仅供追溯；
受支持的验收集是 §1 列出的那一组，`docs/code-map.md` §2.7 有完整清单与标注。

### 4.3 缺陷 C：`SolverStamp` 把不改变 $L$ 的量也算进了失效条件（已修）

`SolverStamp` 决定"是否需要重新数值分解"。它原先把 **pin 位置**与**阻尼**也哈希了进去，
但这两者都**不改变 $L$ 的数值**：

- 被 pin 的行恒为 $(\text{对角}=1,\ b=q)$，对角值与 $q$ 无关；
- 阻尼只体现在速度更新 $v_{n+1}=(1-k_d)(x_{n+1}-x_n)/h$ 上，惯性项始终是未缩放的 $M/h^2$。

后果是拖拽把手或拖动阻尼滑块时白做一次数值分解——而这恰好是交互中每帧都在发生的事，
且与 `docs/plan.md` §2.2.1 "移动把手不触发重分解"的设计约定矛盾。
现在 `pinBits` 只记 **pin 掩码**，`dampingBits` 仅作诊断记录、不参与 `==` 比较；
新增的原语测试 `stampChangesOnlyWhenLeftHandSideValuesChange` 同时断言两个方向：
该变的必须变（刚度/质量/$h$/拓扑/pin 掩码），不该变的必须不变，并**逐位验证 $L$ 确实没变**。
