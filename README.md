# pd_ipc — CPU 版 PD 布料仿真器

首期目标：**纯 CPU 的 Projective Dynamics 布料仿真器**，只含**距离约束 + pin**，跑通完整时间步并带渲染。
规划见 `docs/plan.md`，环境记录见 `docs/environment.md`，开发规范见 `docs/contributing.md`，
代码与命令索引见 `docs/code-map.md`，**收敛成因与刚度标定见 `docs/pd-convergence.md`**。

**当前状态**：整条链路（预测 → PD 迭代 → 全局求解 → 速度更新）已完整跑通，
`pd_check` 8 项验收全通过，三个测试套件 238 个断言全通过，实时渲染可用。
约束集刻意保持在最小（只有距离约束 + pin），**剪切与弯曲约束尚未加入**，见 §5。

> **2026-09-20 更新**：修掉一个真实缺陷 —— **高刚度下 PD 外层迭代在给定预算内
> 远未收敛**，表现为"末端卷曲、摆动被抑制、缓慢下沉"。根因是刚度未标定
> （旧默认 κ=1e5 对应应变 ε=0.023%，远超常规织物量级），而方法的收敛快慢
> 由 ε 决定。已标定到 ε=1%（κ≈2300），残差降两个数量级、60 FPS。
> 完整成因、推导与**排查中被否证的假设**见 `docs/pd-convergence.md`。

.\build\Release\test_primitives.exe        # 距离约束的定义级不变量

.\build\Release\pd_bench.exe --grid 40 40 --steps 600 --iters 10

# 可交互查看器（GLFW + OpenGL）
.\build\Release\pd_viewer.exe

### 3.2 原语不变量 `test_primitives`（12 个测试 / 68 个断言，全过）

**`SolverStamp` 只随"真的改变 $L$ 的量"变化**（拖拽把手/改阻尼不触发重分解，且逐位验证 $L$ 确实没变）、
网格边计数、打包往返。

### 3.3 两顶点弹簧 `test_spring_vertical`（11 个测试 / 155 个断言，全过）

逐步不动点与独立递推参考解逐位一致（$<10^{-11}$）、迭代次数不改变不动点、
离散平衡落在能量极小值、跨 $h$ 的稳态一致、pinned 严格性、能量有界、
**分解复用不变量**（2000 步内分解恒为 1 次；改刚度/$h$/pin 掩码各触发恰好一次，
改 pin 位置/阻尼不触发）。
参考解**刻意手写、不复用 core**，避免"自己验证自己"。

### 3.4 平移不变性与链

- `pd_trans`：无重力且已在静止长度时位移**严格为 0**；pin 平移后相对位移差 $1.9\times10^{-16}$；
  布料平移后边长最大相对差 $1.9\times10^{-12}$。
- `pd_chain`：自由链 400 步后总长与理论严格一致（$N=100$ 时 `4.950000`）；
  悬挂链伸长相对误差随 $\kappa$ 线性下降（$N=400$：$\kappa=10^4$ 时 $3.8\times10^{-2}$，
  $\kappa=10^5$ 时 $3.9\times10^{-3}$），与解析 $\varepsilon_k = k\,mg/(\kappa\ell)$ 吻合。

### 3.5 预分解复用与性能（方向 1 的核心机制）

`pd_bench --grid 40 40 --steps 300 --iters 10`（1600 顶点 / 3120 约束 / 18 线程，
基准自带 κ=1e4，见下注）：

| 量 | 值 |
|---|---|
| $L$ 自由度 / nnz | 4800 / 23496 |
| 符号分解 / 数值分解 | 各 **1** 次 |
| 回代 | 3000 次（累计 432 ms） |
| 单次数值分解 / 单次回代 | 1.10 ms / 0.138 ms |
| 单子步耗时 / 平均迭代 | 3.92 ms / **10.00（撞满上限）** |
| 最终应变 最大 / 平均 | 0.057 / 0.0013 |

阶段占比：全局回代 36.9 %、散射 30.9 %、局部步 18.0 %、组装+分解 0.4 %。

> **与旧版数字的差异（2026-09-20）**：旧记录是"单子步 0.494 ms / 平均迭代 1.76"。
> 那个数字来自**旧判据**（以坐标量级为参照，会过早判定收敛），缩短了迭代数；
> 判据修正后迭代数真实反映收敛难度，故耗时上升约 8 倍。
> 这不是性能退化，而是此前**把未收敛误报为已收敛**。
>
> 另注：`pd_bench` 的 κ 在代码里**显式固定为 1e4**，不跟随 `SceneConfig` 的
> 标定默认值（2300）。因为 2300 是按 60×60、布长 1.18 m 标定的，而基准是
> 40×40、布长 0.78 m，受力更小：同一个 κ 会给出 ε≈15% 且不收敛
> （实测迭代 10/40/100/400 全部撞满、应变恒定在 0.15）。

60×60 布料（3600 顶点 / 7080 约束）在查看器里 `--frames 400` 实测（标定后默认
κ=2300、`residual_tol=0.3`）： **60 FPS**（vsync 封顶）、稳态物理 **1.9 ms/帧**、
迭代 **1** 次、应变 1%、全程数值分解 **1** 次。

> 若把残差门槛收紧到 1e-3（保守档），40 次迭代内达不到，会跑满迭代 →
> 物理 47 ms/帧、约 19 FPS。这个取舍连同门槛与代价的对照表见
> `docs/pd-convergence.md` §4.3。

## 4. 修过的两个真缺陷（排查记录）

首期在"单弹簧平衡"上卡了很久，根因是两个**方向相反**的错误，都值得记下来。

### 4.1 缺陷 A：投影里加了标准 PD 没有的方向翻转（已修）

标准 PD 里 $d_c=\Pi_c(A_cx)=\ell\cdot\mathrm{unit}(A_cx)$，方向由 $A_cx$ **唯一决定**，
且必须与矩阵块 $\kappa A_c^\top A_c$ 来自**同一个** $A_c$。
早期实现在投影里加了"强制指向自由端"的人为翻转（想让 pin 端当支撑），
等于让散射与矩阵块来自不同的 $A_c$。
现在方向只由边的端点顺序 $(a,b)$ 决定，**没有任何 pin 特例**——`_verify/direction_audit.cpp` 的
A 组判据就在钉这一点（三种 pin 配置下 $d_c$ 完全相同）。

### 4.2 缺陷 B：pin 消元的补偿项 $\kappa q$ 漏了（已修，这是主因）

被 pin 的行会被覆盖成 $(L_{ii}=1,\ b_i=\bar x_i)$，等价于把该自由度从方程组中消去。
但耦合块 $-\kappa I$ 里乘 $x_{\text{pin}}$ 的那一项，原本是挂在**自由端那一行**上的 ——
行被覆盖并不会顺手处理它，必须显式搬到自由端的右端：

$$\Bigl(\frac{m}{h^2}+\kappa\Bigr)x_{\text{free}} = \frac{m}{h^2}\hat x_{\text{free}} + \kappa d_c + \kappa\,\bar x_{\text{pin}}$$

漏掉 $\kappa\bar x_{\text{pin}}$ 的表现是**自由端丢失 pinned 点的位置信息**：系统被拉向原点，
无重力、本来就在静止长度时也会自行变形，平移场景后结果改变（`pd_trans` 的第 1 组就是为此设的）。
它还会伪装成"符号错"——因为把坐标原点移到 pin 上时这一项恰好为零，很多场景看不出问题。

排查中另外两处**被我误判**、现已确认实现正确的地方，一并记下以免重蹈：

- **重力只应出现一次**，在预测步 $\hat x = x + hv + h^2g$ 里；右端只有 $(M/h^2)\hat x$，
  再加一个 $-Mg$ 就是重复计入（曾照此"修"过，属于改坏）。
- **平衡位置是 $\ell - mg/\kappa$**（能量极小值），不是 $\ell + mg/\kappa$（那是极大值）。
  符号来自重力项梯度 $+mg$（朝 $-y$）。这一点曾被写反并据此改动实现，是本项目最大的弯路。

`_verify/` 下留了排查期的若干程序（`standard_pd`、`steady`、`rhs_breakdown` 等）。
**它们不是验收工具**，其中一些的前提假设已经过期（有的注释还在按旧结论描述实现），仅供追溯；
受支持的验收集是 §1 列出的那一组，`docs/code-map.md` §2.7 有完整清单与标注。

### 4.3 缺陷 C：`SolverStamp` 把不改变 $L$ 的量也算进了失效条件（已修）

`SolverStamp` 决定"是否需要重新数值分解"。它原先把 **pin 位置**与**阻尼**也哈希了进去，
但这两者都**不改变 $L$ 的数值**：

- 被 pin 的行恒为 $(\text{对角}=1,\ b=q)$，对角值与 $q$ 无关；
- 阻尼只体现在速度更新 $v_{n+1}=(1-k_d)(x_{n+1}-x_n)/h$ 上，惯性项始终是未缩放的 $M/h^2$。

后果是拖拽把手或拖动阻尼滑块时白做一次数值分解——而这恰好是交互中每帧都在发生的事，
且与 `docs/plan.md` §2.2.1 "移动把手不触发重分解"的设计约定矛盾。
现在 `pinBits` 只记 **pin 掩码**，`dampingBits` 仅作诊断记录、不参与 `==` 比较；
新增的原语测试 `stampChangesOnlyWhenLeftHandSideValuesChange` 同时断言两个方向：
该变的必须变（刚度/质量/$h$/拓扑/pin 掩码），不该变的必须不变，并**逐位验证 $L$ 确实没变**。
