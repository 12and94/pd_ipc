# Chebyshev 加速：它是什么、为什么有用、在我们这里怎么用

> 面向"第一次接触这个概念"的读者。所有数字都来自本项目实测
> （工具 `_verify/iteration_spectrum.cpp`，见 `docs/pd-convergence.md` §4.5），不是抄书的。
> 术语对照：本文的 **ρ** 一律指"朴素 PD 迭代每步的收缩率"（Wang 2015 代码里那个 `rho` 变量），
> **ρ_cheb** 指"开加速之后每步的平均收缩率"。

---

## 0. 一句话

**Chebyshev 加速不改每一步"做什么"，只改"这一步迈多大"。**
原来的 PD 每步固定，慢模态每步只衰减 0.9988 倍（我们的稳态实测）；改成每步用一个**专门挑出来的**步长之后，
同样的迭代可以做到每步 0.93 倍 —— 到 1e-2 相对残差从约 3800 次降到约 66 次。

**代价**：多存一份上一步的位置（`4 字节 × 3 × N`），迭代循环里多一个标量递推。
**不改**：装配、分解、局部投影、`L` 的稀疏结构 —— 矩阵还是分解一次用到底。

---

## 1. 先看问题：为什么"每步固定"会卡住

PD 的一次迭代可以写成"误差乘以一个算子"：

```
e_{k+1} = T e_k ,        T = I − A⁻¹(M/h² + N)
```

把误差按 `T` 的特征方向展开（可以理解为**一堆互不干扰的"波"/模态**）：

```
e_k = Σ_i c_i λ_i^k  v_i              |λ_i| ≤ 1
```

每个模态有自己的衰减因子 `λ_i`：

- 有的模态 `λ ≈ 0.1` ⇒ 一步就差不多没了（快模态，通常对应"惯性/局部"的误差）；
- 有的模态 `λ ≈ 0.999` ⇒ 几百步才降一点（慢模态，对应整块布料的整体不协调）。

**整体速度等于最慢那个模态**：`‖e_k‖ ≈ max_i|λ_i|^k`。这就是为什么我们在稳态看到
"残差几乎不动"——不是算错了，是**误差已经只剩慢模态了**。

用我们的实测数（60×60 稳态，κ=2305、h=1/120）：

| 量 | 值 | 含义 |
|---|---|---|
| `λ_max(B)` | 0.9994 | 慢模态的衰减因子（B = I − T） |
| `λ_min(B)` | 0.0012 | 快模态的衰减因子 |
| **ρ = 1 − λ_min(B)** | **0.9988** | 朴素 PD 的每步收缩率（由慢模态决定） |

朴素迭代里我们能调的只有"步长"。但**一个固定的步长无法同时照顾两端的模态**：
把步长调大到让慢模态快一点，快模态就会过冲（甚至震荡）。

---

## 2. 直觉：让"快的人慢下来"，而不是让"快的人更快"

一个类比：一群人从山上往下走，**每个人速度不同**，队伍到达终点的时刻由**最慢的人**决定。
朴素 PD 相当于"所有人每步都迈同样的步子"——最快的人早就到了（甚至来回晃），最慢的人还在慢慢挪。

Chebyshev 的做法是：**允许快的那些人有时原地不动、有时甚至倒退一步**，
把队形整理成"大家同时到达"。听起来荒唐，但对**线性**问题是严格最优的：
因为误差是各模态的线性叠加，允许"系数可变"之后，我们可以设计出一串步长，
让**所有模态的误差被同一个多项式一起压掉**。

（这也是为什么它必须先跑几次普通迭代：一开始队伍是乱的，"倒退一步"没有意义。）

---

## 3. 数学：它变成一个多项式逼近问题

设第 k 步用的步长因子是 `ω_k`（`ω_k = 1` 就是原来的朴素 PD）。迭代可以写成：

```
x_{k+1} = ω_k ( f(x_k) − x_{k−1} ) + x_{k−1}
```

其中 `f` 就是"原本那一步"（局部投影 + 全局求解）。这时误差的传播是：

```
e_T = [ ∏_{k=1..T} ( I − ω_k B ) ] e_0 ,        B = I − T = A⁻¹(M/h² + N)
```

把 `∏(1 − ω_k λ)` 看成一个关于 λ 的 **T 次多项式 P(λ)**，且要求 `P(0) = 1`（因为
`λ = 0` 对应的模态必须不被放大）。我们希望：

```
在 λ ∈ [λ_min, λ_max] 上，让 max|P(λ)| 尽可能小
```

这就是经典的**极小极大多项式逼近**问题，它的解正是**移位缩放后的 Chebyshev 多项式**
（它在一个区间上以"等波纹振荡"的方式最小化最大绝对值；其它多项式做不到更小）。
它的渐近收缩率有一个漂亮的闭式：

```
                √λ_max − √λ_min
ρ_cheb  =  ────────────────────────
                √λ_max + √λ_min
```

**把我们的数代进去**（λ_min = 0.0012, λ_max = 0.9994）：

```
√(0.0012) = 0.0347 ,  √(0.9994) = 0.9997
ρ_cheb = (0.9997 − 0.0347)/(0.9997 + 0.0347) = 0.9325
```

对比一下这两个数：

| 迭代 | 每步收缩率 | 到 1e-2 相对残差需要 |
|---|---|---|
| 朴素 PD（我们稳态） | **0.9988** | ≈ 3800 次 |
| Chebyshev（理论最优） | **0.9325** | ≈ 66 次 |

（`ln(0.01)/ln(ρ)`；这是**渐近**估计，前提是已经进入"只剩慢模态"的阶段。）

### 一个重要的直觉：慢模态越"粘"，收益越大

`ρ_cheb` 只取决于比值 `r = λ_min/λ_max`：

| r = λ_min/λ_max | ρ_cheb | 到 1e-2 需要 |
|---|---|---|
| 1e-6 | 0.998 | 2300 次 |
| 1e-4 | 0.980 | 229 次 |
| **0.0012（我们的实测）** | **0.933** | **66 次** |
| 0.01 | 0.818 | 23 次 |
| 0.1 | 0.520 | 7 次 |
| 0.25 | 0.333 | 4 次 |

`λ_min` 小意味着"约束相对惯性非常硬"（我们的 1/ε 失配：ε=1 % ⇒ 条件数 ~820）。
所以 **布越硬、步长越大、ε 越小，Chebyshev 越值钱**；反过来 `r ≥ 0.25` 时基本没必要上。

## 4. 落地形态：三行递推（Wang 2015 的写法）

```cpp
// 每步：先用原来的 f 算一遍，再按 ω 合成
for (int l = 0; l < iterations; ++l) {
    next_X = f(X);                       // ← 原封不动的 PD 一步
    if      (l <= 10) omega = 1.0;                        // 前 11 步先跑朴素 PD
    else if (l == 11) omega = 2.0 / (2.0 - rho * rho);
    else              omega = 4.0 / (4.0 - rho * rho * omega);
    next_X = omega * (next_X - prev_X) + prev_X;
    swap(X, prev_X); swap(X, next_X);     // 需要保存上一步的 X
}
```

**六个要点**：

1. **`f` 不变**。加速只体现在最后那一步的线性组合上 ⇒ 物理/装配/分解都不动，
   `L` 仍然只分解一次（这是它比"换求解器"便宜得多的原因）。
2. **只用一个数 `ρ`**：它就是朴素迭代的收缩率（我们实测 0.9988）。
   论文里用"连续两次残差的 2 范数之比"在线估计它：`ρ̂ ≈ ‖e^k‖/‖e^{k−1}‖`。
3. **前 S 次必须先跑朴素 PD（`ω=1`）**：一方面让 `ρ̂` 估准（快模态衰减掉之后比值才稳定），
   另一方面避免一开始就过冲。论文取 S = 10；他们也强调 `ρ̂` **宁可取小**。
4. **上表里 94 vs 66 的差别很有用**：只用单个 `ρ` 的递推隐含把谱区间当作
   `[1−ρ, 1+ρ]`（保守），算下来每步 ≈ **0.952**（到 1e-2 约 **94 次**，仍有 ~40× 收益）；
   而我们知道真实区间 `[λ_min, λ_max]`（判据 A 的工具**能算出来**），按最优区间走是每步
   **0.933**（约 66 次）。**这是我们的一个小优势：不必盲估 ρ，可以直接算区间。**
5. **多一份存储**：要保存上一步的 `X`（`prev_X`）。`N = 40000` 时也就 480 KB。
6. **不改变每步的计算量**（仍是"一次局部投影 + 一次回代"），所以**帧率不变、精度变高**。

## 5. 关键：什么时候**不该**开它（我们的实测给出反例）

我们实测过同一状态下的"朴素 PD 每步实际收缩率"：

| 相位 | 朴素实测 | Chebyshev 理论 | 谁快 |
|---|---|---|---|
| 稳态（残差已只剩慢模态） | 0.9988 | 0.9325 | **Chebyshev 快 ~20 倍**（对数意义） |
| **瞬态**（快模态主导） | **0.894** | 0.9325 | **朴素更快** |

也就是说：**在瞬态强行开 Chebyshev 会比朴素更差**。
原因很直观：那套多项式是"为了压慢模态"设计的，在还没进入那个阶段时它在做无用功（甚至倒着走）。

⇒ 正确的形态是"**稳态启用**"：先用朴素 PD 跑到"实测收缩率贴近慢模态（≈0.9988）"，
再打开加速。这和 Wang 2015 "延迟 S = 10 次再开"是同一种保护，只是我们把触发条件从
"固定 10 次"换成"看速率"更稳。

对我们的查看器来说，这正好命中痛点：它 99 % 的时间在稳态，现在的选择是
"1 次迭代（残差停在 0.29·|g|）"或"80 次迭代（到 0.0094·|g|）"。
稳态启用 Chebyshev 的意思是：**同样几次迭代，把稳态残差压到 1e-3 量级** —— 换的是精度，不是帧率。

## 6. 前提与坑

| 前提 | 说明 | 我们满足吗 |
|---|---|---|
| 误差算子有**实**特征值、且谱落在 (0,2) | 否则 Chebyshev 的多项式理论不适用（复谱要另找方法） | ✅ `T = I − A⁻¹(M/h²+N)` 相似于对称矩阵，特征值实且 ∈ [0,1) |
| 能拿到 `ρ`（或谱区间） | 估得要**偏小**；偏大等于把小区间按大区间加速 ⇒ 震荡甚至发散 | ✅ 可直接算（判据 A 的幂迭代），也可在线估 |
| 迭代是**线性**的、且每步是同一个 `f` | 非线性强的时候"每步同一个算子"这个前提会被破坏 | ⚠️ 近似成立（围绕当前位形线性化），这也是"稳态启用"更稳的原因 |
| `ω` 序列不要和 early-exit 混 | 如果每子步只跑 1–2 次迭代就因位移判据退出，加速没意义 | ⚠️ 我们的实时档就是 1 次 ⇒ 要配合"稳态触发 + 多跑几次" |

名词澄清：Gauss-Seidel 版本要先做"一次前向 + 一次后向"以保证特征值为实 —— 我们用**直接法**
处理全局步，不涉及这一条。

## 7. 在我们引擎里落地，会动什么

| 项 | 影响 |
|---|---|
| `core/sim/Integrator.cpp` 的迭代循环 | 加 `prev_X` 缓冲 + `ω` 递推（约 20 行） |
| 装配 / 分解 | **不动**（`L` 不变，仍只分解一次） |
| 每步开销 | 基本不变（多一次位置向量的读写） |
| **数值结果** | **会变** ⇒ 物理基线与门禁第 ④ 步必须重做 |
| 建议形态 | `--cheb` 开关 + 默认关；稳态触发（实测收缩率 > 0.99 时启用）；`ρ` 由我们自己的谱工具给出 |
| 验收 | 判据 A 的工具已经能**预测**收益（算 `λ_min/λ_max` → `ρ_cheb`），做之前就能知道值不值 |

## 8. 速查表

```
朴素 PD：        e_{k+1} = T e_k ,        ρ = ρ(T) = 1 − λ_min(B)
Chebyshev：      e_T = P_T(B) e_0 ,       P_T = 移位缩放的 Chebyshev 多项式
最优收缩率：      ρ_cheb = (√λ_max − √λ_min)/(√λ_max + √λ_min)
递推（论文）：    ω=1 (k≤S)；ω_{S+1}=2/(2−ρ²)；ω_{k+1}=4/(4−ρ²ω_k)
                 x_{k+1} = ω_k(f(x_k) − x_{k−1}) + x_{k−1}
τ 次到相对 ε：    τ ≈ ln(ε)/ln(ρ)

我们的数（60×60、κ=2305、h=1/120、稳态）：
  λ_min = 0.0012    λ_max = 0.9994    ρ = 0.9988    ρ_cheb = 0.9325
  到 1e-2：朴素 ≈ 3800 次 → Chebyshev ≈ 66 次（~57×）；只用单个 ρ 的递推 ≈ 94 次（~40×）
  瞬态（朴素实测 0.894）下不要开。
```
