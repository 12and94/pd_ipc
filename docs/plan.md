## 0. 目标与约束（已锁定）

| 项 | 决策 | 对架构的硬性影响 |
|---|---|---|
| 精度目标 | **实时交互**（60 Hz 帧预算） | 固定/有限迭代而非解到收敛；可用 float32 后端；全局步必须增量复用分解 |
| 网格规模 | **任意大小**（需自适应） | 不硬编码上限；求解器按规模自动选策略（小→直接法，大→迭代法/GPU） |
| 碰撞（初期） | **仅布料–刚体** | 无需自碰撞候选筛选与 EE 对；刚体用位姿查询距离即可 |
| 摩擦 | **先无摩擦** | 局部步只做法向投影，接口保留切向钩子 |
| 方向 2 全局步 | **Chebyshev 半迭代** | 需要 $\lambda_{\min},\lambda_{\max}$ 估计（Lanczos/幂迭代），作为初始化阶段任务 |
| IPC | **暂缓** | 代码中不引入 barrier/CCD，但保留能量项接口（见 §2.5，尚未实现） |
| 起始 | **方向 1：纯 CPU** | M0–M4 交付可交互的实时布料；GPU 从 M5 开始 |
| **首期约束集** | **只做距离约束（弹簧）+ 钉住（pin）** | 约束越少越好：先用两者把"预测 → 局部投影 → 组装 → 预分解全局求解 → 时间循环"整条链路验证到无误，**其他约束（三角形拉伸、二面角弯曲）在链路验证通过后逐个加入**（其规格保留在 §2.2 附录，作为后续输入） | **已经这样做了**：剪切（对角边）与线性（中点）弯曲都已实现，但**默认关闭**（`SceneConfig::shearStiffness` / `bendStiffness`，或 `PD_SHEAR` / `PD_BEND`），所以默认约束集与本文的推导**完全一致** |
| 环境 | 已只读探查并记录 | 见 `docs/environment.md`（MSVC 19.40 / CMake 3.30 / Vulkan SDK 1.3.290 / RTX 4070 Ti / Eigen 3.4.0 本地已有） |
| **铁律** | **禁止参考 `dp_ipc` 工程**（本项目前身）：不读、不搬、不引用、不对照、不依赖其路径。**其他同类实现不设限，可读可引用** | 见 §10.1；正确性只来自独立推导 + 原语不变量 + 解析解对照 |

三个方向的最终形态（同一工程、同一内核、可切换后端）：

| 路线 | 预测 | 局部步 | 全局步 | 计划阶段 |
|---|---|---|---|---|
| **① CPU 多线程** | `parallel_for` (OpenMP) | `parallel_for` | 稀疏 Cholesky **预分解 + 复用回代** | M0–M4（首期交付） |

## 1. 架构总览

### 1.1 分层与依赖方向

```
                 ┌──────────────────────────────────────────┐
   app 层        │  bench(无窗口)   viewer(窗口)   场景/交互  │
                 └───────────────┬──────────────────────────┘
                                 │ 只依赖 core 的公共 API
                 ┌───────────────▼──────────────────────────┐
   core 层       │  Integrator │ Scene │ Metrics │ Config    │   ← 与后端无关
                 └───────────────┬──────────────────────────┘
                                 │
        ┌────────────────────────┼────────────────────────┐
        │                        │                        │
┌───────▼────────┐   ┌───────────▼──────────┐   ┌─────────▼──────────┐
│ backend_cpu    │   │ backend_vk (M5/M6)   │   │ solver 抽象        │
│ 并行内核实现    │   │ 同名内核的 GPU 实现   │   │ IGlobalSolver      │
└───────┬────────┘   └───────────┬──────────┘   └─────────┬──────────┘
        │                        │                        │
        └────────────┬───────────┴────────────┬───────────┘
                     │                        │
            ┌────────▼─────────┐    ┌─────────▼────────────┐
   math 层  │ 数学内核定义/公式 │    │ 内存域 (host/device)  │
            └──────────────────┘    └──────────────────────┘
```

**关键约束（保证三条路线共用一套工程）**

1. **数学内核只用公式定义，不绑定循环实现。** 每个内核以"逐元素纯函数 + 归约语义"描述，CPU 用 `parallel_for` 实现，GPU 用 compute shader 实现，二者有共同契约（§4.2）。
2. **全局求解器只暴露 `analyze/factorize/solve` 三个动词**，调用方不知道背后是 Cholesky 还是 Chebyshev。
3. **内存域（host/device）从 M0 就进入接口签名**，哪怕 M0–M4 只有 host 实现。这是唯一"为将来多付一点复杂度"的地方，但它能避免 M5 时的大规模重构。
4. **渲染与仿真解耦**：先做无窗口 `bench` 可执行文件（CI/性能基线用），再做带窗口的 `viewer`。

### 1.2 核心状态与数据流（单帧）

```
x, v  ──预测──▶ x̂ = x + h·v + h²·g                      [并行, 无依赖]
         │
         ▼
   ┌─ 局部步（可多次）──────────────────────────────┐
   │  for each constraint c:  d_c ← Π_c(A_c x)      │      [并行, 无耦合]
   │  for each vertex v:      b_v ← Σ_c κ_c (A_cᵀ d_c)_v + (m_v/h²)·x̂_v
   │                          （单端 pinned 时另补 κ_c·x̄_pin）      [散射+归约]
   └──────────────────┬─────────────────────────────┘
                      ▼
            全局步：  L x ← b     (L = M/h² + Σ_c κ_c A_cᵀ A_c, 常数)  [预分解+回代]
                      │
                      ▼
         v ← (1−k_d)·(x − xᵗ)/h;  若未达迭代数则回到局部步
```

> 这里的系数与 §2.2.1 严格一致：**惯性项是未缩放的 $M/h^2$**（不是 $M$，也不是 $M/(1-k_d)$ 之类的"有效质量"），
> 阻尼只出现在速度更新的 $(1-k_d)$ 因子上、不进入 $L$。这两点都踩过坑，见 §2.2.1 与 §2.2.2。

实时性来自两个性质：**局部步无耦合（线性加速）**、**$L$ 与位形无关（分解一次反复用）**。

## 2. 数学设计（实现规格）

### 2.1 时间积分与预测

隐式欧拉 + PD 位置求解：

$$M = \mathrm{diag}(m_v),\qquad
\hat x = x^t + h v^t + h^2 g,\qquad v^{t+1} = (1-k_d)\frac{x^{t+1}-x^t}{h}$$

**顶点质量 $m_v$ 的两条路径（口径不同，差 2 倍，务必分清）**

| 路径 | 触发条件 | 公式 | 规则网格内部顶点 |
|---|---|---|---|
| 面积法 `computeMassesFromSurfaces` | `triangleIndices` 非空（**OBJ 载入**） | $m_v = \rho\sum_{t\in N(v)}A_t/3$ | $\rho\ell^2$ |
| 边法 `computeMassesFromEdges` | 无三角形表（**`makeGrid` 程序化生成**） | 每条边给两端各 $\rho\ell^2/2$ | $2\rho\ell^2$ |

- **所有基准、验收场景与查看器都用规则网格，因此走的是边法**：内部顶点 $2\rho\ell^2$、
  边顶点 $1.5\rho\ell^2$、角顶点 $\rho\ell^2$（质量**不均匀**），且无三角形表时
  `computeMassesFromSurfaces` 也会**自动退化**为边法。
- 边法的总质量是面积法的 2 倍。40×40 / 间距 0.025 / $\rho=1$ 时实测总质量 1.9500。
- 手算 $\kappa/m$ 或垂度时若按面积法的 $\rho\ell^2$ 代入，会差 2 倍 —— 这是文档曾经的口径错误。
  若要统一成面积法，必须同时重标定 $\kappa$ 默认值（两者都进 $M/h^2$ 与 $\kappa$ 的比值）。

- 阻尼：速度更新为 $v_{n+1} \leftarrow (1-k_d)(x_{n+1}-x_n)/h$（几何衰减形式，$k_d\in[0,1)$）。
  阻尼系数是全局参数，**不进入 $L$**（因此改阻尼不需要重分解，只影响时间推进）。
  注意静力平衡位置与 $k_d$、$h$ 都无关 —— 静止时 $x_{n+1}=x_n$、$v=0$，不动点方程退化为纯力平衡
  （§2.2.2 第 3 项专门断言这一点；早期文档曾把它写成"缩放有效质量 $M/(1-k_d)$"，那是错的，已撤）。
- 固定步长 $h$（默认 1/120 s），每帧做 $n$ 个子步。**$n$ 目前是配置里的固定值
  （`SceneConfig::substepsPerFrame`，默认 2）；"由帧预算决定"的自适应尚未实现**（属 M3）。

### 2.2 约束集

#### 2.2.1 首期唯一约束：距离约束（弹簧）

每条边（或任意顶点对）$c=(i,j)$，静止长度 $l_c$，刚度 $\kappa_c>0$：

$$A_c x = x_i - x_j \in \mathbb{R}^3,\qquad
E_c(x) = \frac{\kappa_c}{2}\,\bigl\|\,\|x_i-x_j\| - l_c\,\bigr\|^2$$

**全局矩阵（已定，唯一方案）**

$$L \;=\; \frac{M}{h^2} \;+\; \sum_c \kappa_c\,A_c^\top A_c
\qquad\Longrightarrow\qquad
L_{ii} \mathrel{+}= \kappa_c I,\quad L_{jj} \mathrel{+}= \kappa_c I,\quad L_{ij} \mathrel{-}= \kappa_c I,\quad L_{ji} \mathrel{-}= \kappa_c I$$

- 这就是 ADMM（PD）在原始能量上罚项取 $\frac{\kappa_c}{2}\|A_cx-d_c\|^2$ 时给出的矩阵，$L$ **与位形无关**。
- 它**不需要**等于 $E_c$ 的真实 Hessian $\nabla^2E_c=\kappa_c[(1-l_c/r)I+(l_c/r)uu^\top]$。真实 Hessian 是 Newton 类方法的曲率；PD 的收敛性来自"局部步取近端算子 + 全局步解上述常数系统"这一对，不来自曲率一致性。
- $H_c$ 在本项目中的**唯一用途**是校验：对单约束子问题做梯度有限差分对照、验证解析解（M1 验收）。**它不进 $L$。**
- **符号约定（与 `docs/design-discussion.md` 的差异，不是矛盾）**：那里把整条能量乘了 $h^2$（写作 $\frac12\|x-\hat x\|_M^2 + h^2\Psi$），
  于是矩阵写作 $M + h^2\nabla^2\Psi$。两者只差一个整体因子 $h^2$，梯度条件完全相同，
  迭代也一样（把前者的方程整体除以 $h^2$ 即得本文的 $M/h^2$ 形式）。
  文档间看到两种写法时不必怀疑有错；**代码采用本文的未缩放形式**：惯性项是 $M/h^2$，约束项是 $\kappa_c A_c^\top A_c$。
  这一点有实际后果：把惯性项误写成缩放过的 $M/(h^2(1-k_d))$ 之类会改变不动点，测试里专门钉过（§2.2.2 第 3 项）。
- 性质：$L$ 与 $\sum_c \kappa_c A_c^\top A_c$ 同构（加权图 Laplacian 的块形式）+ $M/h^2$，SPD、块对角占优，LDLᵀ 稳定。

> **本项目 CPU 版本不考虑除常矩阵之外的任何左端构造方式。** 具体地说，不做"把几何相关曲率（$\nabla^2E_c$、barrier Hessian、每次迭代重算的 $\nabla\theta$）放进 $L$"的变体。原因不是性能取舍，而是三点：**(a)** 那类构造在 PD/ADMM 的推导下没有依据（标准局部步不产生对应权重）；**(b)** 会让 $L$ 每帧/每迭代变化，摧毁预分解复用（方向 1 的实时性来源）；**(c)** 会让后续接触的 barrier Hessian（量级 ~$\kappa/d^2$）污染矩阵条件数，使 CPU 直接法与 GPU 迭代法同时失效。相关讨论记录在 `docs/design-discussion.md` §5（IPC 部分，暂缓实现）。

**局部步闭式解（投影，$w_c=\kappa_c$）**：

$$d_c = \Pi_c(A_c x) = l_c\,\frac{x_i-x_j}{\|x_i-x_j\|}\quad(\|x_i-x_j\|>0)$$

**组装规则**（$S_c=d_c$；注意 $S_c$ 是**长度为 $l_c$ 的向量**，不是偏移量）：

$$b_i \mathrel{+}= \kappa_c S_c,\qquad b_j \mathrel{-}= \kappa_c S_c,\qquad
L_{ii} \mathrel{+}= \kappa_c I,\quad L_{jj} \mathrel{+}= \kappa_c I,\quad L_{ij} \mathrel{-}= \kappa_c I,\quad L_{ji} \mathrel{-}= \kappa_c I$$

> **右端系数为什么是 $\kappa_c$ 而不是 $2\kappa_c$（一处容易推错的代数）**
>
> 增广能量为 $\tilde E = \frac12\|x-\hat x\|_{M/h^2}^2 + \sum_c \frac{w_c}{2}\|A_c x - d_c\|^2$。
> 对 $x$ 求梯度：$\frac{M}{h^2}(x-\hat x) + \sum_c w_c A_c^\top(A_c x - d_c)$，令其为 0 得
> $$\Bigl(\frac{M}{h^2} + \sum_c w_c A_c^\top A_c\Bigr)x = \frac{M}{h^2}\hat x + \sum_c w_c A_c^\top d_c .$$
> 右端的 $w_c A_c^\top d_c$ **只出现一次**。取 $w_c=\kappa_c$，在一条弹簧上就是 $\kappa_c d_c$；
> 而 $\kappa_c d_c = \kappa_c l_c\,(x_i-x_j)/\|x_i-x_j\|$ 恰好是**线性弹簧力**，因此
> $$\frac{m}{h^2}(x_1-\hat x_1) + \kappa_c\bigl(\|x_1-x_0\|-l_c\bigr)\frac{x_1-x_0}{\|x_1-x_0\|} = 0$$
> 即 PD 的固定点与"线性弹簧 + 隐式欧拉"**严格等价**（§2.2.2 的验收正是建立在这个等价上）。
> 若误写成 $2\kappa_c$，矩阵块里的 $\kappa_c$ 没变、右端却翻倍，等价于把弹簧力放大一倍，
> 单弹簧的固定点会明显偏离真实平衡（首期两顶点实验就是为此设的）。所以这里逐元素断言。

**pinned 顶点的处理（行覆盖 + 消元补偿）**

- pinned 顶点的自由度不作为未知量：其行被覆盖为 $L_{ii}=1$、$b_i=\bar x_i$（把手当前位置）。
- **但涉及 pinned 的弹簧不能整条跳过**：只要还有自由端点，那个端点的对角贡献 $+\kappa_c I$ 必须进 $L$，
  否则该顶点丢掉这份刚度、系统明显偏软。只有**两端都 pinned** 的约束才整条跳过。
- 散射时 pinned 那一端不写 $b$，同时要把"被消去的那一侧"的贡献补到自由端右端：

  $$b_{\text{free}} \mathrel{+}= \kappa_c\,\bar x_{\text{pin}}$$

  推导：耦合块 $- \kappa_c I$ 与 $x_{\text{pin}}$ 相乘的那一项原来挂在**自由端那一行**上，
  行被覆盖成 $(1,\bar x)$ 并不会顺手处理它。换句话说，正确的单弹簧全局步是

  $$\Bigl(\frac{m}{h^2}+\kappa\Bigr)x_1 = \frac{m}{h^2}\hat x_1 + \kappa d_c + \kappa x_0 .$$

  **漏掉 $\kappa\bar x_{\text{pin}}$ 的后果**：自由端丢失 pinned 点的位置信息，系统被拉向原点 ——
  无重力、本来就在静止长度时也会自行变形，平移场景后结果改变。这是一个"看起来只差一点"的
  静默错误，本项目实际踩过（详见 `README.md` §4）；现在 `tests/primitives` 有逐分量断言钉住它。
- $L$ 的稀疏结构不变（这些行本来就有对角元，只会因跳过弹簧而少几个非零元）→ **不影响分解复用**。
- 覆盖后的行不参与任何耦合 ⇒ 解出 $x_i=\bar x_i$ **精确成立**，可作为严格断言（M1 验收 5）。

**单弹簧（两顶点）解析解 —— 这是一个可精确对照的规格，见 §2.2.2**

一个自由端点 1、一个 pinned 端点 0，$k=\kappa$：

$$x_1 = \frac{\frac{m}{h^2}\hat x_1 + k\,P + k\,x_0}{\frac{m}{h^2} + k},\qquad P=l\,\frac{x_1-x_0}{\|x_1-x_0\|}$$

（$P$ 在上一次迭代的 $x_1$ 处求值；每迭代重新投影一次，交替直至不动点。
分子里除惯性项外只有 $kP$（散射）与 $kx_0$（pin 消元补偿）两项，各出现一次。）

#### 2.2.2 两顶点弹簧竖直实验（验收规格）

**装置**：$x_0=\mathbf 0$ 固定；$x_1=m$ 的自由质点，初始位置/速度由场景指定；重力 $g$ 沿 $-\hat y$；弹簧静止长度 $\ell$、刚度 $k$。这是首期唯一约束集下**可完全手算**的最小系统。

**离散不动点的闭式解**。隐式欧拉步（预测 $\hat y_1=y+h v-h^2g$）的固定点满足

$$\frac{m}{h^2}\bigl(y-\hat y_1\bigr)+k\bigl(y-\ell\bigr)=0
\qquad\Longleftrightarrow\qquad
y^\star=\frac{m\,\hat y_1+k h^2\ell}{m+k h^2}$$

- 由于弹簧力是线性的（$r>\ell$ 与 $r<\ell$ 只是方向不同、形式相同），**上式对拉伸与压缩两个分支都成立**，不需要分段。
- **该式与代码的等价性不是近似**：PD 势能 $E_c=\frac{k}{2}(r-\ell)^2$ 的梯度恰为 $k(r-\ell)$（线性弹簧力），故"PD 固定点 = 弹簧隐式欧拉解"。
- **两顶点弹簧（本装置）下，一次 PD 迭代就精确到达不动点**：局部投影恒为 $d_c=-\ell\hat y$、
  与当前位形无关，矩阵又已含 $k$，所以迭代次数 1 / 5 / 50 给出**逐位相同**的结果
  （实测差 0，见 `test_spring_vertical` 第 2 项）。注意这只对本装置成立：
  自由链这类多约束系统仍需几百次迭代才收敛（见第 9 项）。

> （60×60、间距 0.02、密度 1 下对应顶端应变 ε≈1%）。标定依据、质量口径依赖、
> 以及标定前高刚度下"外层迭代不收敛"这一缺陷的完整成因见 `docs/pd-convergence.md`。
> **注意**：κ 与网格尺度强相关（ε 取决于受力与边长），换网格需重标定；
> `pd_bench` 因此在代码里显式固定自己的 κ，不跟随该默认值。

#### 2.2.4 附录：三角形拉伸规格（**后续实现，现在不写**）

每个三角形 $t$：$F_t = [x_1-x_0,\ x_2-x_0]\,\bar F_t^{-1} \in \mathbb{R}^{3\times2}$，其中 $\bar F_t$ 为静止形变梯度。
约束矩阵 $A_t = \frac{1}{\sqrt{2}}\,\mathrm{vec}(F_t)\in\mathbb{R}^{6}$（$c_t = \|A_t\|^2 = \frac{1}{2}\|F_t\|_F^2$）。

$$d_t = \frac{1}{\sqrt 2}\mathrm{vec}(U\Sigma' V^\top),\qquad
\Sigma' = \mathrm{diag}(\mathrm{clamp}(\sigma_1),\ \mathrm{clamp}(\sigma_2)),\quad
\mathrm{clamp}(\sigma)=\min(1+\epsilon,\max(1-\epsilon,\sigma))$$

- $U,\Sigma,V$ 由 $F_t$ 的 $3\times2$ SVD 得到（`Eigen::JacobiSVD` 或手写无分配版本）。
- 权重 $w_t = k_{\text{stretch}}\cdot A_t^{\text{rest}}$（面积加权，尺度无关）。
- $\epsilon=0$ → 每三角形近似刚性（PD 原文的非拉伸约束）。

#### 2.2.5 附录：二面角弯曲规格（**后续实现，现在不写**）

每条内部边 $e$：$C_e = \|\nabla\theta\|(\theta-\bar\theta)$（满足 $C^\top C = \nabla\theta^\top\nabla\theta$，与位形无关），

$$d_e = \|\nabla\theta\|\,\bar\theta,\qquad w_e = k_{\text{bend}}$$

- $\nabla\theta$ 依赖位形 → 每帧局部步开始时算一次（D3）。退化解（共面/退化三角形）用阈值跳过。

#### 2.2.6 已实现的弯曲：线性（中点）形式（2026-09-22，**可选约束**）

实际落地的是"沿行/列连续三个顶点"的**线性（中点）**弯曲，不是 §2.2.5 的二面角形式：

$$A_c x = x_a - 2x_b + x_c,\qquad E_c(x) = \frac{k}{2}\|A_c x\|^2
\qquad\text{（等价于：}x_b\text{ 与两邻居中点之间挂一根静止长度为 0 的弹簧）}$$

**选它的唯一理由**是下面四条**结构性**收益，它们直接决定"改动面有多大"：

| | 线性中点形式 | 二面角形式（§2.2.5） |
|---|---|---|
| $A_c$ 是否常数 | ✅ 常数 ⇒ $L$ 与位形无关 ⇒ **只分解一次**（§2.3 不变量 1） | ❌ $\nabla\theta$ 依赖位形 |
| 矩阵块形状 | ✅ $k\,w_pw_q I_3$（$w=\{1,-2,1\}$）⇒ 仍是标量 × I₃ ⇒ **$L=\tilde A\otimes I_3$ 与三分量并行保住** | ❌ 一般 3×3 块 |
| 局部步 | ✅ 流形 $\{x:A_cx=0\}$ 是**线性子空间** ⇒ 投影 $p_c\equiv 0$ ⇒ **无事可做** | ❌ 投影非零 |
| 右端 | ✅ 只多一个**与位形无关的常向量**（仅当 stencil 含 pinned 顶点时非零） | ❌ 每迭代都变 |

**装配规则**（$w=\{1,-2,1\}$；$F$ = stencil 内非 pinned 顶点集，$C=\sum_{t\in\text{pinned}} w_t q_t$）：

- 左端：对 $p,q\in F$ 在块 $(p,q)$ 加 $k\,w_pw_q I_3$。
  ⚠️ **pinned 列必须为 0**（不能照抄距离约束那条"只跳两端都 pin"的规则）——
  被 pin 的行被覆盖为 (对角 1, 右端 $q$)，这套消元法只在 pinned 列在自由行里全为 0 时自洽；
  否则 $L^\top$ 回代会把 $x_{\text{pin}}$ 从 $b_{\text{pin}}=q$ 上顶回去。
  本项目实测踩过：矩阵变**不定**、求解器**不报错**、解全错（见 `docs/perf.md` §12.6 局限 5）。
- 右端：对 $p\in F$ 加常向量 $-k\,w_p C$（全自由 stencil ⇒ $C=0$ ⇒ 零贡献）。
- 残差：$f_v = \sum_{\text{stencil}\ni v} -k\,w_v (A_c x)$ —— **必须算进残差**，
  因为残差是唯一放行判据，少算一项力就是**假阴性**。

**已知局限**（都写进了 `docs/perf.md` §12.6）：等效抗弯刚度 $\propto s^4/k$（网格相关，换分辨率要重标定）；
端点不生成 stencil ⇒ 边界是**自由端**（自然边界条件）；静止曲率**恒为 0** ⇒ **不能表达目标曲率/预折痕**。
实测代价 **+73 %**（因子 nnz 2.77×，几乎全在回代上）⇒ **默认关闭**（`SceneConfig::bendStiffness = 0`）。

### 2.3 全局矩阵 $L$ 的组装与复用规则

采用常矩阵时：

$$L \;=\; \underbrace{M/h^2}_{\text{对角}} \;+\; \sum_t \kappa_t\,A_t^\top A_t \;+\; \sum_e \kappa_e\,A_e^\top A_e
\qquad(M=\mathrm{diag}(m_v),\; m_v=\rho\!\!\sum_{t\ni v}\! A_t/3)$$

- **`L` 数值只依赖**：拓扑、刚度 $\kappa$、质量 $m$、子步长 $h$、pin 掩码。**不依赖 $x$** → 这是方向 1"预分解"成立的全部理由。
- 显式写出 $M/h^2$（而不是把 $h$ 折进质量）便于换子步长时判断失效。

> **不变量（本节的核心，必须作为断言写进测试）**
> 1. **帧内绝对不变**：在一个时间步的 PD 迭代循环内，$L$ **一次都不重新组装、不重新分解**；每迭代变化的只有右端 $b$（因为 $d_c$ 变了）。这是"预分解 + 反复回代"成立的全部理由。
> 2. **跨帧只在 stamp 事件上变**：拓扑（含撕裂/重网格）、材料刚度 $\kappa$、子步长 $h$（经 $M/h^2$）、pin 掩码。除此之外的任何帧都不允许触发重分解。
> 3. **各组成项为何与 $x$ 无关**：$A_c$ 只是拓扑的常数编码（距离约束为 $(e_i-e_j)\otimes I_3$；三角形约束为 $\frac{1}{\sqrt2}\mathrm{vec}(F)$，其系数由**静止**形变 $\bar F^{-1}$ 定），不含当前位置；$w_c$ 是材料参数，局部步更新的是目标 $d_c$ 而非权重；$M$ 由静止几何算出。**旋转类局部标架（ARAP / shape matching）进入右端 $A_c^\top R_c$，不进左端。**
> 4. **非线性全部去右端 / 局部步**：这正是 PD 的分工，也是接触能挂上来的原因 —— 接触不做成 barrier Hessian 进 $L$，而做成局部步的可行集投影（见 `docs/design-discussion.md` §5）。
> 5. **测试方式**：`tests/primitives/test_distance_term.cpp` 的
>    `stampChangesOnlyWhenLeftHandSideValuesChange` 断言"该变的必变、不该变的必不变"
>    （并逐位验证改 pin 位置/阻尼后 $L$ 相同）；
>    `tests/chain/spring_vertical.cpp` 的 `globalMatrixIsFactoredOnceAndReused`
>    断言"2000 步内分解恒为 1 次；改 $\kappa$ / 换 $h$ / 改 pin 掩码各触发恰好一次"。
>    —— 这两条是**已有实现**的不变量门禁；新增任何"失效条件"前先确认它们仍然通过。
> 6. **注意不要说过头**：不是"$L$ 永远不变"，而是"帧内不变 + 跨帧只在上述事件上变"。某些 PD 变体（每次迭代重算 $\nabla\theta$、把 exact Hessian 放进矩阵、mode switching）是**故意**放弃这个性质的，代价就是失去复用 —— 我们选择不这么做（D2/D3）。
- **失效（需重分解）的条件必须显式建模**，用一个 `SolverStamp`：
  `{ topology_id, stiffness_hash, mass_hash, h, pin_mask_hash }` —— 任一变化才重分解。
  - 拓扑不变 + 刚度不变 → **只在启动时分解一次**，之后每帧只做回代（这正是实时性的来源）；
  - 运行中拖刚度滑块 → 触发重分解。做法：**去抖（~150 ms）+ 后台线程分解 + 原子换入**，主线程不 stall；
  - 换子步长 $h$（帧预算自适应会做这件事）→ 只影响 $M/h^2$ 的对角，仍是重分解。**为避免每帧都在改 $h$ 导致反复重分解，$h$ 的调整策略要按"档位"（如 1/60、1/120、1/240）切换并去抖**，不要连续微调。
- **pin 的处理**：见 §2.2.1 —— 装阶段**只跳过两端都 pinned 的约束**，单端 pinned 时自由端的
  对角 $+\kappa$ 仍进 $L$；pinned 行填 $(1,\bar x_v)$；散射时把被消去侧的 $\kappa\bar x_{\text{pin}}$
  补到自由端右端。稀疏结构不变 → 拖拽把手**不触发重分解**（只改 $b$ 的对应行）。
- 正定性：$M/h^2$ 严格正定（$m_v>0$），故 $L$ SPD，Cholesky/LDLᵀ 无虞。退化保护：若 $m_v < 10^{-12}$ 取全局最小值兜底。

### 2.4 CPU 侧"预分解 + 每次全局步求解"的具体做法

这是方向 1 的核心机制，逐环节写清楚。

**（1）存储与结构：块 3×3 还是标量展开**
- 标量展开 CSR：$3N\times3N$（每顶点 3 个标量自由度）。起步用这个，配 Eigen 的 `SparseMatrix<double>`（列主序 CSC）；本项目按 (i,j) 块写入时用 `triplet` 累加。
- 块存储（每非零块一个 `Mat3`）：更省内存（省 ~2/3 索引开销）且 SpMV 访存更友好，但 Eigen 无原生支持，需自写。**首期不做**，留到 M2 若 profiling 显示索引开销显著再上。
- 稀疏结构（哪对 $(i,j)$ 有非零块）**只依赖拓扑**：预先从边表构建一次，之后永久复用。这是后面 `analyzePattern` 能复用的前提。

**（2）三个操作粒度（必须分开，不能糊成一个"分解"）**

| 操作 | 何时做 | 代价 | 代码位置 |
|---|---|---|---|
| `analyzePattern`（符号分解 / AMD 排序 / 消去树） | 拓扑变化时（通常**一次**） | 中等，随 nnz 增长 | `EigenDirectSolver::analyze` |
| `factorize`（数值分解） | `SolverStamp` 变化时（启动、改刚度、换 $h$、拓扑变） | 大（本机制的成本主体） | `EigenDirectSolver::factorize` |
| `solve`（前代 + 回代） | **每次全局步** | 小，$\propto \mathrm{nnz}(L)$ × 右端数 | `EigenDirectSolver::solve` |

- 后端：`Eigen::SimplicialLDLT<SparseMatrix<double>>`（本机无 CHOLMOD）。它默认用 AMD 排序且支持 `analyzePattern` / `factorize` 分离调用 → 天然适配上表。
- **不要**用 `SimplicialLLT`（Cholesky）：本矩阵数值范围跨多个量级，LDLᵀ 更稳；也不要每帧重建矩阵对象（会丢掉排序与符号结构）。

**（3）每次全局步的求解流程（热路径，逐帧执行）**

```
每帧：
  for 每个子步:
    1. 预测        x̂ = x + h·v + h²·g                         [并行]
    2. b = (M/h²)·x̂                                            [并行，含 0 初始化]
    3. PD 迭代（k = 1..K）:
         a. 局部步   d_c = l_c·(x_i-x_j)/‖x_i-x_j‖               [并行，无依赖]
         b. 散射     b_i += κ_c d_c ;  b_j -= κ_c d_c          [并行 + 归约]
                     若某一端被 pin：那一端不写 b，改为给自由端补 b_free += κ_c·x̄_pin
         c. 覆盖 pin 行：b_i = x̄_i（i ∈ pinned）
         d. 全局步   solve(L, b) → x                             [回代，一次]
         e. 收敛检查：‖x^{(k)}-x^{(k-1)}‖_∞ / ‖x̂‖_∞ ≤ τ
    4. 速度更新    v = (x - x_prev)/h ; 阻尼 v *= (1-k_d)
```

- 第 3.b 步必须在**每次迭代**重新累加（因为 $d_c$ 变了），所以 $b$ 要么每迭代重建，要么保存 $\hat b=(M/h^2)\hat x$ 并每迭代从它拷贝一份（推荐：**预分配 K 份 $b$ 缓冲**，避免重复分配）。$L$ **只在第 3.d 步被用到**，且数值不变。

**（4）批量化右端（把"每次全局步"的成本压到最低）**
- Eigen 的 `solve` 支持矩阵右端：`solver.solve(B)`，$B\in\mathbb{R}^{3N\times K}$ 一次解 $K$ 个右端。前代/回代对每个右端各做一遍，但**符号结构遍历与内存访问模式复用**，实际比循环调用快。
- 两种用法：
  - **顺序 PD**（迭代 $k$ 的 $d$ 依赖 $x^{(k)}$）：每迭代一次 `solve`，右端数 $K=1$。这是标准做法。
  - **块 PD / 多子步批处理**：若将来做"一个子步内多个独立右端"或"多分辨率"，用 $K>1$。
- **首期按 $K=1$ 实现但接口留成矩阵右端**，这样后续想换批处理不用改求解器接口。

**（5）分解的成本时序（为什么这套机制划算）**

| 时刻 | 操作 | 典型量级（200×200，40k 顶点，~120k 标量 DOF） |
|---|---|---|
| 启动 | `analyzePattern` + `factorize` | 符号分解 + 数值分解：数十 ms 级 |
| 每帧 × 60 | `solve` | 每次 1 次回代：ms 级 |
| 拖刚度滑块 | 重分解（后台 + 去抖） | 数十 ms 级，不落在帧内 |
| 改子步长档位 | 重分解（去抖） | 同上 |

- **判定标准（M2 必须量化）**：令 $t_f$ 为一次数值分解耗时、$t_s$ 为一次回代耗时、$K$ 为每帧迭代数
  （注意：**每个子步有 $K$ 次回代**，因为每次 PD 迭代都要解一次全局系统 —— 见 §2.4(3) 的伪码；
  容易误写成"每个时间步只需 1 次全局求解"，那会把全局步成本低估 $K$ 倍）。
  - **加速比** $= \dfrac{K(t_f+t_s)}{K\cdot t_s + t_f} \xrightarrow[K\to\infty]{} 1 + \dfrac{t_f}{t_s}$
    —— 分子是"每步都重分解"的耗时，分母是"分解一次 + 反复回代"的耗时。
  - 写成"收益比"的倒数形式 $(K t_s+t_f)/(K(t_f+t_s))$ 会小于 1，容易被读反，这里统一用加速比。
  - 40×40（1600 顶点）实测：$t_f=1.08$ ms、$t_s=0.135$ ms ⇒ 极限加速比 $\approx 9.0\times$。
    这就是方向 1 的核心卖点，M2 要在多规模上把这个数测出来。

**（6）并行的位置与不并行的位置（诚实说明）**

> **当前实现状态：只有局部步投影与散射是真正并行的。** 下表其余各项都是**待办（M2）**。

| 阶段 | 计划 | 现状 |
|---|---|---|
| 预测 $\hat x=x+hv+h^2g$ | 并行 | **串行 for**（`Integrator.cpp` 第 1 阶段） |
| 局部步投影 $d_c$ | 并行 | ✅ `parallelFor`（`DistanceTerm::project`） |
| $b$ 重建 `b = bBase` | 并行 | **串行**（Eigen 赋值） |
| 散射 $b\mathrel{+}=\kappa d_c$ | 并行 + 归约 | ✅ OpenMP + 线程私有缓冲（边数 $\ge256$ 才走并行分支） |
| 收敛判据归约 | 并行 | **串行 for** |
| 速度更新 | — | **串行 for** |

- **基本串行**：Eigen 的稀疏三角求解（前代/回代）**是单线程的**，且没有"回代并行"的开关；`factorize` 也基本单线程（Eigen 内部不并行化稀疏 LDLᵀ）。
  - 因此：**不要把"多线程"的期望压在全局步上**。方向 1 的加速来自局部步与组装；全局步的快来自"分解复用"而非并行。
  - 若回代成为瓶颈（大网格），可走的路径：换多线程的稀疏直接法（CHOLMOD + 多线程 BLAS，本机未安装，需自建，见 Q4）→ 或直接上 M6 的 GPU Chebyshev。
  - **2026-09-22 补注（实测推翻了"不要把多线程的期望压在全局步上"这条）**：本项目**不需要**
    并行化三角求解**本身** —— `L` 的每一块都是标量 × I₃（`L = Ã ⊗ I₃`，见 `Assembler.cpp` 与
    `DistanceTerm::assembleMatrix`），它的图是 **3 个互不相连的连通分量**，所以 3n 个方程本来
    就是 3 个互不相干的标量系统：按 x/y/z 拆成 3 条**零同步**的独立链即可，实测单次回代快
    2.0–2.8×、主工况 −42.3 %，且**物理输出逐位不变**（`docs/perf.md` §9、
    `parallel-refactor.md` 的 Phase 4c）。上面那条"可走的路径"（CHOLMOD / GPU Chebyshev）
    因此都不是必需的。

### 2.5 能量项接口（为 IPC 预留，现在不实现）

```cpp
// core/energy/EnergyTerm.h  —— 一个能量项 = 一组约束 + 局部投影 + 组装
class IEnergyTerm {
public:
  virtual ~IEnergyTerm() = default;
  virtual uint32_t constraintCount() const = 0;
  // (1) 局部步：d = argmin ||A x - d||²/w + Ψ(d)   —— 逐约束独立，纯函数
  virtual void project (const Domain& x, Domain& d, Domain& w) const = 0;
  // (2) 组装：b += Σ w_c A_cᵀ d_c
  virtual void scatter (const Domain& d, const Domain& w, Domain& b) const = 0;
  // (3) 矩阵：把 w_c A_cᵀ A_c 累加进 L 的 CSR（只在 stamp 变化时调用）
  virtual void assemble(uint64_t stamp, SparseMatrix& L) const = 0;
  // (4) （MPC/摩擦/收敛诊断用，PD 主循环不调用）真实能量、梯度
  virtual double energy  (const Domain& x) const { return 0.0; }
  virtual void   gradient(const Domain& x, Domain& g) const {}
};
```

- `StretchTerm`、`BendTerm` 是这套接口的**后续**实现；首期只有 `DistanceTerm`。接口之所以按"约束类型分派"设计，是因为局部步与组装本来就是按约束类型分派的，不是为了将来才抽象。
- **首期的关键简化**：只有一个 `DistanceTerm` 时，`project` 是逐边闭式解、`scatter` 是两次加法、`assemble` 是秩一块散射 —— 整条链路可以在几十行内核里被完全看懂，这是"约束越少越好"的目的。IPC 的 `BarrierTerm`（接触作为可行集投影）将来只是第三个实现。
- 不引入 `hessian()`，因为 PD 主循环不用它。若将来需要做 Newton 类方法的对照（数值微分或解析 Hessian），再在子类上加，不影响接口稳定性。

> **2026-09-22 的实现注记：这个接口至今没有落地，而"线性（中点）弯曲"（§2.2.6）把它该承担的三件事各自放到了别处。**
> 这不是偷懒，而是那条约束的结构决定的 —— 它**没有局部步、没有散射**（投影恒为 0），
> 所以 `IEnergyTerm` 的两个主要方法（`project` / `scatter`）对它都是空实现，为它引入一整套
> 虚接口只会多一层间接、而收益是零。于是它的三件事分别落在：
> **① 局部步**：无事可做（这正是选这个形式的理由之一）；
> **② 组装**：`core/assemble/Assembler.cpp` 的 (2b) 段（块 $k\,w_pw_qI_3$）+ `assembleBendingRhs()`（常向量右端）；
> **③ 残差**：`core/sim/Integrator.cpp` 的 `bendForceAt()` —— 残差不在 `IEnergyTerm` 的原始设计里，
> 而它现在是**唯一放行判据**，所以每个新能量项都必须在这里补一项（漏了就是假阴性）。
>
> **真正需要这套虚接口的时机是"约束数量增长到需要按类型分派"**（IPC 的 barrier、摩擦、
> 三角形拉伸同时在场）。届时这张"三件事分别在哪"的清单就是接口的规格：
> 一个能量项 = 局部投影 + 组装（含它的右端项）+ **残差力** —— 第三项是本轮补上的、
> 原设计漏掉的那一条。

### 2.6 收敛判据（实时版本）

$$\text{stop when } \|x^{(k+1)}-x^{(k)}\|_\infty \le \tau_{\text{abs}} \ \ \text{or}\ \ \|x^{(k+1)}-x^{(k)}\|_\infty / \|\hat x\|_\infty \le \tau_{\text{rel}}$$

- 默认 $k_{\max}=10$，$\tau_{\text{rel}}=10^{-3}$（实时允许粗糙）。
- 另设**帧预算保护**：若单帧已耗时超过预算的 60%，本轮子步提前退出并降级迭代数；下帧回升。
- 一致性检查（`bench` 用，非实时路径）：解到 $\tau_{\text{rel}}=10^{-10}$，用于验证直接法求解器本身。

### M1 — 单步隐式求解（正确性优先，可慢）（预计 3–4 天）

> **本里程碑的交付物首先是一组"原语不变量"断言，其次才是求解器。** 一条距离约束的投影，其**返回向量的长度必须恰好等于静止长度** —— 这是定义本身，不是派生量。先把这条断言写成测试并让它通过，再看任何派生指标（残差、能量、垂度）。顺序颠倒的代价是：一个量级错误会被一堆互相印证的派生指标掩盖。

**产物**
- `DistanceTerm`：投影（含 $\|x_i-x_j\| < \epsilon_{\text{len}}$ 的退化保护）、组装（$L$ 的常数块 $+\kappa_c I / -\kappa_c I$，只跳过两端都 pinned 的约束）、$b$ 的散射（$\kappa_c d_c$ + pin 消元补偿）。

- 组装并行：per-thread `b` 缓冲（$3N$ double）→ 归约；$L$ 的**稀疏结构**在启动时建一次，**数值**只在 `SolverStamp` 变化时重装（$L$ 与位形无关）。
- 求解器后端可切换：`EigenDirectSolver`（`SimplicialLDLT`，**本机唯一的直接法后端**；CHOLMOD 未安装，若 Q4 确认需要再自行构建 SuiteSparse）。
- `Metrics`：各阶段耗时（预测/局部/散射/组装 $L$/$t_{\text{analyze}}$ 符号分解/$t_f$ 数值分解/$t_s$ 回代/收敛/总计）、迭代数、能量、$\|x^{(k+1)}-x^{(k)}\|$、**stamp 值与重分解计数**。
- 基准脚本 `bench/sweep.ps1`：网格规模 × 线程数 × 迭代数，输出 CSV + Markdown 表。

**验收**
- 与 M1.5 单线程版本**逐位可比**（同初值同迭代数，相对误差 $<10^{-12}$）—— 并行不改变数学；若因归约顺序产生 $10^{-12}$ 以上的差异，说明并行方案有实质缺陷而非舍入。
- 8 线程相对单线程在局部步上加速 $\ge 5\times$（$N\ge 40\text{k}$）；**不承诺 20×**（E-core 混构）。
  <br>**2026-09-22 注（建议改成带宽效率口径）**：该判据在 200×200 上实测只有 **2.36×**，
  且论证下来是**平台带宽上限**而非实现缺陷 —— 局部步每次调用读写约 8.3 MB，1 线程已达
  ~17 GB/s（单核带宽极限），8 线程 ~40 GB/s ≈ 该平台双通道峰值的 **78 %**；要 5× 需要
  ~85 GB/s，超过硬件能力。**建议改为"≥70 % 平台峰值带宽"这类带宽效率口径**（详见
  `docs/perf.md` §4 与 `docs/open-issues.md` §2.6）；改判据属于规格变更，按 `README.md` 的
  "实时状态以 README 为准"约定，本条**保留原文**、只加此注。
- **分解复用收益被量化**（§2.4(5)(6)）：分别测出 $t_f$（数值分解）、$t_s$（一次回代）、$t_{\text{analyze}}$（符号分解）随顶点数的曲线，给出收益比 $(K t_s+t_f)/(K(t_f+t_s))$ 的数字。同时确认 $t_s$ 与 $t_f$ **不随并行线程数下降**（Eigen 稀疏三角求解是单线程）—— 把这条写进性能模型，避免误判瓶颈。
- **不做左端方案的对照实验**：CPU 版本只做常矩阵（§2.2.1、D2），没有第二个候选需要比较。给几何相关曲率进矩阵的讨论保留在 `docs/design-discussion.md` §5 作背景材料，不进入 M0–M4 工作范围。
- 首次得到**实时预算表**（见 §6），并确认瓶颈阶段。

### M3 — 完整时间循环与交互（预计 3–4 天）

**产物**
- `Integrator`：预测 → PD 迭代 → 速度更新 → 阻尼 → 子步循环 → 帧预算保护。
- pin / 拖拽把手：行替换为 $\alpha I$、右端 $\alpha\bar x_v$，运行中移动把手不触发重分解；**pinned 顶点位移严格为 0**。
- `viewer` 可执行文件：**GLFW 3.3.8（本机已有 vc2022 版）+ OpenGL** 或 Vulkan 渲染；绘制布料线框/实体、重力开关、暂停/单步、迭代数滑块、耗时 HUD。
- 自适应策略：规模自适应（$N$ 小→直接法；$N$ 大→M6 的迭代法入口）+ 帧预算自适应（§2.6，尚未实现）。
- **后台重分解**：$\kappa$ 变化时去抖 + 后台线程重算 $L$ 数值并重新分解，完成后原子换入（避免 UI 拖动刚度时卡帧）。
- 刚度默认值来自 M1.5 的标定记录，不再用拍脑袋的值。

**验收（可交互性）**
1. 60×60 网格（3.6k 顶点）在 8 线程下稳定 $\ge 60$ FPS，单帧求解 $<5$ ms。
2. 200×200（40k 顶点）可达 $\ge 30$ FPS（迭代数 10）。
3. 交互操作（拖拽、改刚度、开关重力）不产生卡顿 > 50 ms 的长帧。
4. 数值稳定：连续 10 000 步无 NaN/Inf；**距离约束的相对误差有界**（无三角形翻转检测 —— 首期只有距离约束，不引入面翻转判据）。

### M4 — 正确性与性能回归固化（预计 2–3 天）

**产物**
- `tests/`：
  - `primitives`：M1 的原语不变量（投影长度/方向、组装与梯度一致性、矩阵块比对）—— **作为常驻测试**，不允许以一次性脚本或临时程序替代。
  - `chain`：M1.5 的链路检查（规格见 §3，目前只实现了两顶点弹簧）。
  - `physics_regression`：悬挂布（固定两角）下垂 → 与基线解的 L∞ 误差在阈值内；能量曲线存档对比。
  - `invariants`：代理能量单调、pinned 顶点精确满足、$L$ 对称正定（Cholesky 成功）。
  - `stability_sweep`：$h \in \{1/60,1/120,1/240\}$ × $\kappa \in \{10^2..10^5\}$ × 迭代数 $\{5,10,20\}$ 的稳定性矩阵（NaN/爆炸/刚度敏感性检测）。

**验收**：全部测试 headless 通过；性能表覆盖 3 档网格规模与 1–16 线程；扩展性曲线能回答"纯 CPU 直接法在多大规模上失效"。

## 4. 后续里程碑（GPU，同一工程内演进）

### M5 — 路线 ③：Vulkan compute 局部步 + CPU 全局步

**目标**：把"高并行部分"换成 compute shader，全局步仍走 CPU Cholesky（复用 M2 的 `IGlobalSolver`）。

| 工作项 | 说明 |
|---|---|
| Vulkan 基础设施 `vk/` | instance/device/queue、显存分配（**VMA 未安装**：先用 `vkAllocateMemory` + 自写子分配，或引入单头 VMA）、pipeline 缓存、descriptor set 布局、pass graph（`vkCmdPipelineBarrier` / `synchronization2`）、staging buffer 双缓冲 |
| 内核移植 | 预测、距离约束投影、$b$ 的散射、能量/残差归约（首期约束集小，移植面窄 —— 这正是"先砍约束"的收益） |
| 归约方案 | **不依赖 float 原子**：subgroup 归约（实测 subgroupSize=32、shuffle/arithmetic 全支持）+ 每 workgroup 槽位 + 二趟归约；`VK_EXT_shader_atomic_float` 存在（`_float2` **不存在**）故仅作可选快速路径 |
| 精度 | float32 热路径（`shaderFloat64` 硬件支持但吞吐 1/64，仅用于诊断内核）；$b$ 与 $\hat x$ 用 Kahan 补偿求和；判据用相对残差 |
| 传输 | 每子步只传 $b$（$3N$ float）、回传 $x$；双缓冲 + 跨帧流水（`timelineSemaphore` 可用），避免 stall |
| 共享内存 | **48 KB / workgroup**（实测上限，非 64 KB）：分块归约与暂存按此设计 |
| 后端切换 | `--backend cpu\|vk_local`；两条路径**同场景同初值的数值对照测试**（容差 $10^{-4}$ 相对） |

**验收**：40k/250k 顶点场景下 `vk_local` 总耗时不劣于纯 CPU；数值与 CPU 版在容差内一致；切换后端不改变场景代码。

### M6 — 路线 ②：Vulkan Chebyshev 半迭代全局步

**目标**：把全局步搬到 GPU，得到全 GPU 路径。

| 工作项 | 说明 |
|---|---|
| 谱估计 | 启动时用 Lanczos 或幂迭代估计 $\lambda_{\max}$；$\lambda_{\min}$ 用下界估计或自适应 Chebyshev 上界 → 得到 Chebyshev 参数（$\lambda_{\min}$ 与质量/刚度尺度相关，换 $\kappa$ 后需重估） |
| 求解内核 | CSR SpMV（按行并行 + subgroup 归约；矩阵是**常数块 $3\times3$ 对角块**结构，常矩阵下可按需转成标量块存法）、逐顶点块（$3\times3$）Jacobi 预条件、Chebyshev 三向量递推；全部记录在同一 command buffer |
| 迭代控制 | 固定迭代数（实时）与相对残差判据（可选）；残差写入 host-visible 小缓冲，**只回读 4–8 字节** |
| 收敛对比 | 与 CPU 精确解对比：迭代数 vs $\|Lx-b\|$ 曲线；与 M2 的直接法做同场景耗时对比 |
| 规模自适应 | 决策表：$N < N^\*$ 用 CPU 直接法；$N \ge N^\*$ 用 GPU Chebyshev（$N^\*$ 由 M5/M6 基准实测确定） |
| 备选升级 | 若 Chebyshev 迭代数仍过大：graph-colored Gauss–Seidel、子空间预条件（SA'23 思路）、几何多重网格（长期项） |

**验收**：250k 顶点布料达到 $\ge 60$ FPS（$k=10$，Chebyshev 迭代数由基准决定并记录）；数值与直接法解在有意义容差内一致；给出"何时该留在 CPU"的实测决策表。

## 6. 性能预算与基准（实时期望值）

单帧 16.6 ms，其中物理预算目标 $\le 5$ ms（留 10 ms 给渲染）。下表的"约束数"按**首期 4-邻域距离约束**计（$2n_xn_y-n_x-n_y$）；追加三角形约束或弯曲约束后需重新标定。

| 网格 | 顶点 | 约束数（4-邻域边） | 局部步 8 线程 | 散射+组装 $b$ | 全局回代 $t_s$ ×K | 预期帧率 |
|---|---|---|---|---|---|---|
| 60×60 | 3.6k | 7.1k | <0.1 ms | <0.1 ms | <0.1 ms | ≥60 FPS 余量大 |
| 200×200 | 40k | 79.6k | 0.3–0.8 ms | 0.3–0.8 ms | 0.5–2 ms | ≥30–60 FPS |
| 500×500 | 250k | 499k | 2–5 ms | 2–5 ms | 5–30 ms ⚠ | 需 M6 GPU 全局步 |

> 表中**不含**分解耗时：常矩阵下 $t_{\text{analyze}}+t_f$ 只发生在启动与偶发事件（改刚度 / 换 $h$ 档位 / 拓扑变化），不进每帧预算 —— 这正是采用常矩阵的目的。偶发事件的处理见 §2.3（去抖 + 后台分解 + 原子换入）。

> ⚠ **需要实测确认的假设**：
> 1. 大网格的**串行回代可能成为方向 1 的天花板**（顶点数增长带来 fill-in 超线性）。这是 M6 存在的量化理由，M4 的扩展性曲线必须把这条画出来。
> 2. 采用常矩阵后 **$L$ 与位形无关 → 正常运行时每帧只做回代，不做分解**；分解只发生在启动与"改刚度 / 换 $h$ 档位 / 拓扑变化"这些偶发事件上。因此实时性模型是"$t_f$ 摊到事件上 + 每帧 $K\cdot t_s$"，而不是"每帧 $t_f+t_s$"。
> 3. **"每帧重分解"的对照数据仍要测一次**（M2）：只是为了给"分解复用"的收益一个数字（$t_f$ 与 $t_s$ 之比），不是为了评估别的方案。收益比 $=(K t_s+t_f)/(K(t_f+t_s))$ 是方向 1 的核心卖点，必须给出实测值。

**基准方法学**：固定初值与固定迭代数；预热 100 帧后统计 600 帧的均值/P95/最大值；报告每阶段耗时与占比；所有数值可复现（固定 CV 种子或程序化网格）。

## 7. 关键决策记录（Decision Log）

| # | 决策 | 备选 | 影响 / 理由 |
|---|---|---|---|
| D1 | **首期只做距离约束 + pin**；三角形拉伸与二面角弯曲延后 | 一开始就做三种约束 | 约束越少，整条链路的每个数字都可手算核对；多机制同时在场时，缺陷之间会互相掩盖 |
| D2 | 全局矩阵**只用常矩阵** $L=M/h^2+\sum_c\kappa_cA_c^\top A_c$；**CPU 版本不考虑任何其他左端构造** | 把几何相关曲率（$\nabla^2E_c$ / barrier Hessian / 每迭代重算的 $\nabla\theta$）放进 $L$ | 常矩阵是 PD = ADMM 在原始能量上取二次罚项时**推导出来的**结果，不需要等于真实 Hessian；那类变体在推导下无依据、会让 $L$ 每帧变（摧毁预分解复用）、并使后续 barrier Hessian 污染条件数。$H_c$ 仅保留作有限差分校验用（§2.2.1） |
| D3 | 右端显式写 $\kappa_c d_c$ 与矩阵块同源的 $\kappa_c$ | 引入 $w_c=\kappa_c/2$ 之类的"半边"约定 | 矩阵块与散射必须来自**同一个** $A_c$ 且系数一致；两处各写一份、再在 `tests/primitives` 里逐元素断言，比"靠命名约定隐藏常数"更不易错 |
| D4 | 分解拆成 **`analyzePattern` / `factorize` / `solve`** 三段，失效由 `SolverStamp` 判定 | 把"分解"当一个操作，每帧重建矩阵对象 | 符号结构与排序只依赖拓扑 → 可永久复用；三者混在一起会导致每步都在重做符号分解，把实时性吃掉（§2.4(2)） |
| D5 | 子步长 $h$ 按**档位**切换并去抖 | 连续微调 $h$ 做帧率自适应 | $h$ 进入 $M/h^2$，连续调整等于每帧重分解；档位化把重分解限制在偶发事件（§2.3） |
| D6 | 局部步 = **逐约束独立闭式投影**；多约束顶点由全局步耦合 | 对多约束顶点求"真 prox / 小局部线性系统" | 标准 PD（= ADMM 特例）就是前者，对该能量收敛；后者是方向性误解，会引入无谓的非线性局部求解 |
| D7 | 首期**不用原子加**，用线程私有缓冲 + 二次归约 | atomic / 图着色 | 确定性（可做逐位回归测试）；且该方案可原样映射到 GPU（规避对 float atomic 扩展的依赖）。**2026-09-21 更新（Phase 2）**：CPU 侧机制改为**约束图着色**（同色边互不相邻 ⇒ 无需归约、也无需原子加）；决策的**实质不变**（不用浮点原子加、结果与线程数无关、可映射到 GPU），只是手段不同。实测颜色数 40×40 为 6；跨线程数与重复运行**位级相同**。见 `docs/parallel-refactor.md` Phase 2 与 `docs/perf.md` §3 |
| D8 | CPU 数值用 **double** | float | 参考实现的正确性优先；float32 只在 GPU 后端引入，并用对照测试约束 |
| D9 | 内核契约**公式化 + host/device 域参数** | 先写死 CPU、M5 再重构 | 唯一提前付出的复杂度，换 M5 不做大重构 |
| D10 | 渲染与物理**解耦**，`bench` 无窗口 | 直接做带窗口的 Vulkan 应用 | CI 与性能基线必须 headless；渲染后端 M3 再定（见 Q3） |
| D11 | 全局步接口按**矩阵右端**设计（$K$ 个右端一次解），首期按 $K=1$ 用 | 循环调用单右端 solve | Eigen 的 `solve(B)` 能复用符号遍历与访存模式；接口留成矩阵右端后，将来做批处理/MR 不用改求解器 |
| D12 | **不指望全局步并行**：局部步与组装并行，前代/回代按串行预算 | 期待多线程加速直接法回代 | Eigen 稀疏三角求解是单线程的；把并行期望压在全局步上会导致性能模型失准（§2.4(6)）。<br>**2026-09-22 补充：这条决策被实测推翻了** —— 本项目**不需要**并行化三角求解内部：`L = Ã ⊗ I₃`（每块都是标量 × I₃）⇒ 图是 3 个互不相连的连通分量 ⇒ 按 x/y/z 拆成 3 条**零同步**的独立链即可，主工况 **−42.3 %** 且物理输出**逐位不变**（`docs/perf.md` §9、`parallel-refactor.md` Phase 4c）。"Eigen 的三角求解是单线程"这句话仍然为真，但它不再构成天花板 |
| D13 | 方向 2 全局步用 **Chebyshev 半迭代** | 裸 Jacobi / CG / 多重网格 | 成本与 Jacobi 同阶、收敛显著更好；需要谱估计（M6 前置任务） |
| D14 | **【铁律】禁止参考 `dp_ipc` 工程**：不读源码、不搬代码、不引用其结论与参数、不与其对照、不依赖其路径 | 读该工程的实现或结论以省时间 | 它是本项目前身（同作者、同假设、同 PD 内核的早期形态），用它当参照会毁掉本轮"独立推导 + 原语不变量 + 解析解对照"的第二意见（缺陷 A/B/C 正是这样漏掉的）。**注意范围：只锁这一个工程，其他同类实现可参考**。详见 §10.1。~~原表述为"禁止参考任何外部同类实现（本机工作区中其他目录下的项目一律在内）"~~，该范围已作废 |
| D15 | 测试**自包含**（单头 doctest 或自写断言），且**原语不变量优先** | 先写求解器、测试后补 | 投影的量级是定义的一部分，必须先被断言；否则一个量级错误会被一堆互相印证的派生指标掩盖 |

## 8. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| **预分解失效条件判断错误**（误判为"无需分解"或"每帧都要分解"） | 前者给出错误解且不报错；后者吃掉实时预算 | `SolverStamp` 显式覆盖拓扑/刚度/质量/$h$/pin 五项；Metrics 里记录 stamp 与重分解计数；测试中主动制造每种失效并断言"确实重分解了" |
| **回代在中等网格上就吃掉预算**（串行、Eigen 单线程） | 250k 顶点时方向 1 无法实时 | M4 画扩展性曲线定位拐点；M6 的 GPU Chebyshev 兜底；或自建多线程 CHOLMOD（Q4） |
| 帧预算内迭代数不足导致布料过软/抖动 | 观感/物理质量 | 迭代数自适应 + 阻尼调节 + 刚度标定（M1.5）；必要时降 $h$ 增子步 |
| 缺少弯曲约束导致褶皱不真实 | 交付质量 | 首期接受（只有距离约束的布料无褶皱），M4 之后按 §2.2.3 顺序追加 `BendTerm` 并固定"悬挂布褶皱"回归基线 |
| float32 GPU 后端精度不足（M5/M6） | 与 CPU 解偏离、能量漂移 | 相对残差判据 + Kahan 求和；容差对照测试作为门禁（不通过不上线） |
| 20 逻辑核含 4 个 E-core，加速比低于预期 | 实时预算估错 | 基准按 1/2/4/8/16 线程呈现；线程数运行时可配；不承诺线性加速 |
| 手工编译/环境配置踩坑（INCLUDE/LIB、无 Ninja、无 vswhere） | 浪费起步时间 | 已记录 `docs/environment.md` §3.1 的可复用命令与三个踩坑点 |
| 接口过早抽象导致过度设计 | 开发效率 | D8 只覆盖内核签名与求解器三动词，不引入插件注册/反射等机制 |

## 9. 开放问题

- **Q1 GPU 硬件能力** —— ✅ **已探明**：见 `docs/environment.md` §2（RTX 4070 Ti；`shaderFloat64` YES 但吞吐 1/64；`VK_EXT_shader_atomic_float` YES 而 **`_float2` NO**；subgroup=32 且运算全支持；共享内存 48 KB；显存 11.7 GB；单 buffer 上限 4095 MB）。M5/M6 的方案已按此定稿。

## 10. 项目铁律

### 10.1 禁止参考 `dp_ipc` 工程

本项目的**唯一**隔离对象是 `D:\dsh_workspace\dp_ipc` 这一个工程，**不是**"所有外部同类实现"。对它可以读、可以借鉴、可以对照、也可以引用其结论；对 `dp_ipc` 则六条全禁：

| 禁止项 | 说明 |
|---|---|
| 不读其源码 | 求解器、碰撞、约束、网格、渲染、着色器、测试，一概不读 |
| 不搬运 | 不复制任何代码片段、数据结构、参数默认值、配置文件 |
| 不引用其结论 | 其文档、推导、调试记录、"已验证"结论一律不作为本项目的依据 |
| 不与其对照 | 不做"和它对齐 / 比它更好"的验证；本项目的对照物只有**解析解**与**不变量** |
| 不依赖其路径 | 构建配置、脚本、测试一律使用本项目内相对路径，不引用 `dp_ipc` 的任何路径 |
| 不留痕迹 | 本项目的代码注释、文档、提交信息中不得出现对该工程的引用 |

**为什么只隔离这一个工程**：它是本项目的**前身**——同一批作者、同一套建模假设、同一个 PD 内核的早期形态。把它当作参照物，等于让一个已知含未修缺陷的早期版本替本轮独立推导背书；缺陷 A/B/C（见 `README.md` §4）正是"自己验证自己"会漏掉的那类错误。隔离的目的是保住本轮"独立推导 + 原语不变量 + 解析解对照"的**第二意见**，与"对外部实现一律设防"是两件事。

**对其他工程放开的部分**（`learn_cloth`、`about_houdini` 等）：源码、文档、方案、参数都可以读、可以引用、可以对照。但正确性的**最终判据**不变——仍然只能来自独立推导、原语不变量断言与解析解对照；参考别人的结论不等于验证过。环境与工具链经验（踩坑记录、构建脚本写法）可以直接复用。

**历史说明**：本节与 D14 原本写的是"禁止参考任何外部同类实现（本机工作区中其他目录下的项目一律在内）"。那条范围过大，既无独立理由，又挡住可用资料，已按上述范围收窄。方法论（正确性只来自独立推导 + 不变量 + 解析解）**未变**。

**执行**：写进 `docs/contributing.md` §1；CI 增加一项文本扫描，只检查对本工程 `dp_ipc` 的引用，命中即失败。

> **为什么要注明"只扫这一个"**：旧 CI 规则写的是 `dsh_workspace\\[^\\]+`——它连本项目自己的路径都会命中，
> 按字面执行**第一次就会因 `docs/code-map.md` 里的 `cd D:\dsh_workspace\pd_ipc` 而失败**。
> 一条会自我失败的门禁等于没有门禁；现在的扫描目标与隔离范围严格一致。

### 10.2 其他铁律

1. **先断言原语，再断言派生量**：投影的长度、组装与梯度的一致性属于定义级不变量，必须最先有测试（§2.2.1、M1 验收 1）。
2. **不接受口头结论**：任何"已验证"都必须指向一条可重跑的断言。
3. **近似必须显式**：任何为性能引入的近似（如 M2 的 $H_c$ 更新阈值、M5/M6 的 float32 路径）都必须在文档与测试中显式标注，不允许静默降级。
4. **状态单一来源**：不允许存在两套并行的状态表示（网格 vs 解向量）而不做严格一致性断言（M1.5 第 6 项要求严格为 0）。
5. **不引入包管理器、不联网获取**（单头测试/UI 库的一次性获取需在本项目内记录来源与版本）。
